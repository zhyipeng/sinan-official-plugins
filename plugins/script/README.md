# 脚本

`tools.script` 0.2.0。在司南搜索「脚本」打开管理页。添加一个或多个本地目录，即可扫描目录中的 .py、.js、.sh 文件。列表和司南全局搜索均支持文件名、去扩展名的名称及单独设置的多个关键字。选中全局搜索结果即可运行。每个脚本可关闭「在全局搜索中显示」，管理页仍保留该脚本。

- **目录** — 扫描直接子文件，目录中的符号链接可手动导入。扫描结果短暂缓存，可手动刷新。
- **环境** — 按 PATH 查找 `python2`、`python3`、`python`、`node`、`sh`，同名取首个可执行路径。手动环境由名称和可执行文件组成。Python 先匹配显式的 Python 2 或 3 shebang；其余 Python 脚本依次使用 `python3`、`python`、`python2`。JavaScript 和 Shell 分别匹配 Node 和 sh。脚本的设置可覆盖自动匹配。
- **导入与创建** — 导入只登记所选文件，保留原文件。其他格式默认尝试直接执行，可指定解释器。创建时选择已添加的目录、输入文件名及可选初始内容。同名文件会提示冲突。
- **运行** — 以脚本所在目录为工作目录。「运行时打开输出页」默认关闭，后台执行完会通过系统通知显示成功或失败及短输出。输出超过 512 字节的通知预算时，通知提示查看临时日志。开启输出页后可查看合并的标准输出、标准错误和退出状态。输出页预览最多 16 KiB，较长输出可在临时日志中查看。管理页的「结果」可查看最近一次执行和日志位置。

## 兼容性

最低宿主版本为 Sinan 0.6.0，使用 UI Bridge 2、`file.pickPath` 和 `notifications.send`。插件需要信任原生进程，解释器和脚本以当前用户权限运行。

macOS 和 Linux 的直接执行需要执行位；带 shebang 的脚本由系统处理。Windows 的直接执行支持本机 .exe/.com，.py/.js 使用本机解释器，.sh 依赖 PATH 上的 `sh.exe` 或合适的手动环境。应用从桌面启动时可能看不到终端初始化的 PATH，可以通过「添加环境」指定二进制。Linux 桌面选择器依赖宿主的 GTK3/WebKitGTK，X11 和 Wayland 待各自实机验证。

`npm run build:script` 构建当前目标，追加 `-- --all` 可构建六目标。现有打包命令会收集构建产物。

macOS 系统通知需要应用包及系统通知授权。Windows 依赖系统 Toast，Linux 依赖会话 D-Bus 和桌面通知服务。系统通知不可用时，执行结果仍可在管理页查看。
